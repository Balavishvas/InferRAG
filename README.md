# InferRAG 🧠\n\n> An evidence-driven RAG system that retrieves relevant knowledge and produces grounded answers.\n> **V2.2:** universal document ingestion → metadata-aware chunking → persistent FAISS retrieval → optional local LLM.\n\n## V2.2 architecture\n\n```\nPDF / DOCX / PPTX / XLSX / TXT / MD / CSV / Images\n                         ↓\n                 Universal Loader\n                         ↓\n          Normalized text + source context\n                         ↓\n             Metadata-aware Chunking\n                         ↓\n               Local Embeddings\n                         ↓\n             Persistent FAISS Index\n                         ↓\n              Semantic Retrieval\n                         ↓\n                Relevant Evidence\n                         ↓\n                 Optional Ollama\n                         ↓\n                      Answer\n```\n\nInferRAG is being built in stages. The core idea remains evidence-driven RAG: retrieve evidence first, then add reranking, hypothesis generation, verification, and uncertainty modeling on top of that evidence.\n\n## V2.2 features\n\n- PDF, TXT, Markdown, CSV ingestion\n- Word `.docx` ingestion, including paragraphs and tables\n- PowerPoint `.pptx` ingestion, including slide text and tables\n- Excel `.xlsx` ingestion, preserving sheet boundaries and rows\n- PNG, JPG, JPEG, WEBP and BMP image ingestion through local OCR\n- Overlapping chunks with source/chunk metadata\n- Persistent FAISS indexes saved under `data/index/`\n- Automatic index reuse when the document and retrieval settings are unchanged\n- Local sentence-transformer embeddings\n- FAISS semantic retrieval\n- Top-k evidence retrieval\n- Optional local Ollama generation\n- Evidence shown with every answer\n- No paid API required\n\n### Image note\n\nV2.2 treats images as evidence through OCR. It extracts readable text from an image and sends that text through the normal RAG pipeline. Full vision-model understanding of charts, diagrams, and non-text visual content is intentionally reserved for a later multimodal reasoning stage.\n\nImage OCR requires the Python packages in `requirements.txt` plus the **Tesseract OCR engine** installed on the local machine and available on `PATH`.\n\n## Setup\n\n### 1. Create a virtual environment\n\n```bash\nuv venv\n```\n\nWindows PowerShell:\n```powershell\n.\.venv\Scripts\Activate.ps1\n```\n\n### 2. Install dependencies\n\n```bash\nuv pip install -r requirements.txt\n```\n\nThe first use downloads `all-MiniLM-L6-v2` and then runs embeddings locally.\n\n### 3. Test retrieval\n\nPut a supported file inside `data/documents/`, then run:\n\n```bash\npython app.py "data/documents/example.pdf" --query "What is this document about?"\n```\n\nThe same command works with supported `.docx`, `.pptx`, `.xlsx`, `.csv`, `.txt`, `.md`, and OCR-readable image files.\n\n### 4. Optional local LLM with Ollama\n\nInstall Ollama, then:\n\n```bash\nollama pull qwen2.5:3b\n```\n\nThen:\n\n```bash\npython ask.py "data/documents/example.docx" --query "What are the main findings?"\n```\n\n## Project structure\n\n```\nInferRAG/\n├── app.py\n├── ask.py\n├── requirements.txt\n├── rag/\n│   ├── loader.py\n│   ├── chunker.py\n│   ├── embeddings.py\n│   ├── vector_store.py\n│   ├── llm.py\n│   └── pipeline.py\n├── data/\n│   └── documents/\n└── tests/\n```\n\n## Roadmap\n\n- [x] V1 — Basic local RAG\n- [x] V2.1 — Better chunk metadata and persistent retrieval index\n- [x] V2.2 — Universal multimodal document ingestion\n- [ ] V2.3 — Reranking\n- [ ] V2.4 — Retrieval evaluation and context selection\n- [ ] V3 — Hypothesis generation\n- [ ] V4 — Evidence verification\n- [ ] V5 — Confidence and uncertainty modeling\n- [ ] V6 — Knowledge graph\n- [ ] V7 — Redis and semantic caching\n- [ ] V8 — Evaluation benchmarks\n- [ ] V9 — Cloud deployment\n\n## Design principle\n\nEvery component should solve a real problem.
